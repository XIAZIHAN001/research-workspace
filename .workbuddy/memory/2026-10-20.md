## 用户反馈修复轮（commit 38b83bc）

用户提了 3 个问题，我**先读图实测再定位**，其中 2 个的根因与用户判断不同：

**① 深色文字重影** —— 实测截图 chroma spread 仅 8/255（JPEG 压缩伪影），
min/max 跨度来自截图降采样 ⇒ **PDF 页面上的彩色边不是渲染 bug**。
真正原因（Windows）：`-webkit-font-smoothing: antialiased` 保留了次像素抗锯齿，
亮字在暗底上产生彩边；`text-rendering: optimizeLegibility` 在中文回退字体上
产生不均匀笔画。
修复：`[data-theme='dark']` 下切 `grayscale` + 1px 暗色 text-shadow，移除 optimizeLegibility。
**同时实测了 WCAG**：全部 dark level 下最差 tertiary-on-panel = 5.47:1（AA 需 4.5:1）
⇒ **不需要动任何 token 值**。这一步避免了 wrongly "fixing" 合规的颜色。

**② 侧栏宽度/收起** —— 两侧收起逻辑**代码里早就存在**（左侧 `useSidebar` + `.reopen`，
右侧 `panel === null` → rail），真正缺的是：
- 左侧折叠按钮 28px 无边框低对比 → 图上几乎看不见 ⇒ 加 `.sidebar-collapse` 永久描边 + hover 填充
- 两侧都**不能调宽度** ⇒ 新增拖拽把手（`role="separator"` + `aria-valuenow/min/max` +
  Arrow/Home/End 键 + 双击复位）、pointer capture、宽度持久化 + clamp
- `.reader-side` 原为硬编码 `flex: 0 0 360px` ⇒ 改 `var(--panel-w)`
- 关键坑：`.sidebar` 原 `overflow: hidden` 会裁掉外伸的把手 ⇒ 改 `overflow-x: visible;
  overflow-y: hidden`（只裁纵轴）

**③ 论文导入** ——
- 新增 `pdfjs.ts: readPdfMetadata() / parsePdfMetadata()`：读 PDF Info 字典
  （Title/Author/CreationDate/Subject/Keywords）
- 信息字典是**不可信自由文本**，每字段都要过滤：LaTeX 花括号组与 `\and` 展开、
  arXiv 的 YYMM 前缀（2401）不能当年份、DOI 要剥掉句子标点
- 只填**空字段**，绝不覆盖已填内容；用 token 防止上一个文件的慢读串到当前文件
- 替换原生 `<input type="file">` 为样式化 drop zone，但**真 input 保留在树里**
  （只视觉隐藏、不 aria-hidden），保留选择器/拖放/键盘/读屏全部路径

**验证**：tsc 0、eslint 0、vitest 1357 passed / 30 failed —— 失败集与改动前基线
完全一致（此前已用 stash 验证），零回归。新增 `pdfjs.test.ts` 11 个测试。

**经验**：用户报"重影"时先测量再下结论——我差点加了一条
`-webkit-font-smoothing` 到 `.pdf-canvas` 的**假规则**（该属性只影响 DOM 文本，
对 canvas 像素无效），及时发现并撤掉了。
