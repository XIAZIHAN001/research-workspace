## P1 修复：75% 缩放重叠 + 深色阅读渲染（用户报两个 P1）

### P1-1 缩放重叠（根因：尺寸被二次乘缩放）
`PdfPage` 测量时用 `page.getViewport({ scale })`（带当前缩放）上报，`ReaderView.heights` 又乘一次 scale → 槽位高度 = 页面高 × scale²。100% 时恰好正常（×1），75% 时槽位 490px < 页面 632px，重叠 142px。
修：`PdfPage` 改为 `getViewport({ scale: 1 })` 上报**本征尺寸**（用 reportedRef 按 size key 去重，缩放变化不再重复触发 onMeasure）；`ReaderView` 的 `heights` 已是 `(measured ?? baseSize.height) * scale`，语义对齐。实测 75% 槽位 632 = 页面 632，gap 16px 正常。

### P1-2 深色阅读文字发虚彩边（根因：LCD 子像素抗锯齿 + pdf.js alpha:false）
现象：深灰模式下文字红蓝彩边、发空。pdf.js 6.4 内部 `canvas.getContext('2d', { alpha: false })` → 不透明画布 → Chromium 启用 LCD 亚像素抗锯齿 → 文字边缘红/蓝像素有真实 chroma → 被"彩色像素保留"规则原样跳过 → 深底彩边。
排查弯路：pdf.js `render({ background })` **默认值是 '#ffffff'**（`background || "#ffffff"`），传 undefined 无效；即使传 'transparent'，只要走 `canvas` 参数，pdf.js 自己 getContext 也是 alpha:false。
修（`PdfPage.tsx`）：
- 改传 `canvas: null, canvasContext: <自建 alpha:true context>`（pdf.js 只在 canvas 为 null 时才用 canvasContext）。透明画布上 Chromium 只能灰阶抗锯齿 → 文字边缘 = 黑+部分 alpha → 重着色映射到 ink 同 alpha → 锐利无毛边。
- `background: palette === 'original' ? '#ffffff' : 'transparent'`（'transparent' 是合法 fillStyle，填充等于不填；纸色由 `.pdf-page` 背景提供，无接缝）。
- recolour 直接在自建 context 上 getImageData/putImageData（willReadFrequently），删掉 work canvas 中转。
- keptOriginal（图像页）时页面背景回退 #ffffff，否则黑字压深底不可读。
`paperTheme.ts`：`measurePage` 里 alpha==0 像素**计入分母但不计 dark/colour**（透明=纸面；既不能算黑墨也不能从分母剔除，否则文本页会被误判 image-heavy）。
弃用方案：pdf.js 原生 `pageColors`（HCM）= 整页灰度化+线性映射，会摧毁图表色彩，违背"不改图片语义"原则。

### 经验
- pdf.js 6.4 的 canvas 透明渲染必须走 canvasContext（canvas: null），`background` 默认白、falsy 也会白。
- LCD AA 只发生在不透明画布；深色重着色前先确认 AA 来源，"彩边像素被保留"是子像素 AA 的确定信号。
