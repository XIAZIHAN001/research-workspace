## 一、结论

1. **AI 只能提出建议，不能写入事实。** 模型返回名称、引文、依据类型和解释；它不能提供 id、页码或确认状态。服务端逐字校验引文与页码归属，浏览器再把名称映射到稳定概念 ID，所有新增记录强制为 `status: suggested / origin: ai`。
2. **每条关系都带着自己的出处。** 关系证据是独立的 `ConceptEvidence`，记录论文、文件哈希、页码、原文和验证级别；接受关系不会把模型解释写进读者的 `note`。
3. **先本地、后模型，且必须两次明确点击。** 「查看相关知识」只读本地图谱；「分析知识关联」只生成上下文计划；只有「开始分析」才发出一次 `/api/ai/knowledge` 请求。
4. **上下文完全本地检索、可解释、有上限。** 轻量 BM25 式词项评分 + 定义句式 + 邻近页/笔记/难点，最多扫描 48 页、发送 6 页、6000 字；计划逐段列出来源页码、字数、理由、截断与碎片化。
5. **确认后才进入依赖图。** 重复关系、循环前置、错误方向、无效端点、重复概念均在服务端和领域层双重拒绝；学习路径只使用已确认的前置关系。
6. **备份兼容。** Phase 8 字段是可选的增量字段，知识 schema 仍为 v1，备份格式仍为 v1；Phase 7 形状的备份可在新应用恢复，新增建议、确认关系和证据又能导出并在全新浏览器恢复。
7. **离线验收。** `verify:knowledge-ai` **48/48**；全部既有浏览器套件回归 **263 项全绿**；`npm run check` **59 文件 / 1254 项**；构建通过。
8. **Mock 边界明确。** 所有浏览器验收使用 `ai:serve:offline`，结果在界面上标注「本地模拟（mock provider）」，不能作为真实模型的学术能力证明。

## 三、架构决策

### 3.1 数据模型：增量字段，不升级 schema

先审查了 Phase 6/7 的 `Concept`、`ConceptEvidence`、`ConceptRelation`：

- `Concept.status/origin/projectIds` 已能表达「建议 / 确认」和「AI / 用户」，无需修改。
- `ConceptRelation.note` 是读者自己的话，不能用来存模型解释；关系出处无法只在 note 里可靠保存。
- 因此采用**可选增量字段**，知识 `version` 仍为 `1`，备份格式仍为 `1`：
  - `ConceptRelation` 新增可选 `support`（`direct | inferred | external`）、`rationale`、`provider`、`providerLabel`、`model`、`rulesVersion`、`evidenceIds`。
  - `ConceptEvidence` 新增可选 `relationId`、`verification`（`verbatim | located | unverified`）。
- 旧 payload 没有这些字段时，严格解析器照常接受；新 payload 的交叉引用（`relationId` ↔ `evidenceIds`）在严格解析时校验，悬空即拒绝整份备份。
- 没有执行数据库式迁移，因为不需要：字段是加法，读取路径兼容。

### 3.2 协议：名称而非 ID

模型永远看不到本应用的 id，也不能提交页码。请求只包含：论文引用、选中的原文、若干带页码的段落、已有概念名称/别名、已确认关系（仅用于去重与循环检测）。响应只包含概念名称、引文、`support`、`direction`、解释。所有映射在本机完成。

### 3.3 检索：本地 BM25 式索引，不引入向量库

PDF 文本用 pdf.js `getTextContent()` 提取，不渲染页面。页数、段落数、字符数三层上限；计划先生成、后发送。没有 embedding API、没有向量数据库、没有网络请求。

### 3.4 阅读器交互：低干扰入口

选区工具栏新增「查看相关知识」；它打开与 AI 助手/难点/笔记并列的侧栏标签。打开面板、生成计划都不调用模型；结果区明确区分「本地已有知识」「已有概念的新出处」「概念建议」「关系建议」。

## 四、Task A：AI 概念与关系建议

### 4.1 接口

`POST /api/ai/knowledge`（本地服务，127.0.0.1，与 ask/difficulties 相同的 Host/Origin/大小/频率/并发/取消守卫）。

请求关键字段：

| 字段 | 约束 |
| --- | --- |
| `paper` | id、标题 ≤300、当前页、SHA-256 |
| `passages` | ≤8 段；每段 ≤2000 字；合计 ≤9000 字；唯一页码 ≤6；恰好一段 `selection` |
| `existingConcepts` | ≤60 个；名称 ≤80；别名 ≤8 个 |
| `existingRelations` | 仅 `confirmed`；用于重复和循环判断 |

响应关键字段：

| 字段 | 含义 |
| --- | --- |
| `status` | `valid / recovered / malformed / incomplete` |
| `concepts[]` | `name, aliases, summary, support, evidence[], evidenceStatus, existing?` |
| `relations[]` | `from, to, kind, direction, support, explanation, evidence[], evidenceStatus` |
| `rejected / rejectedDetails` | 被服务端拒绝的条数与代码/简短原因 |
| `diagnostics` | rawChars、保留/拒绝数量、重复、方向默认、忽略的身份/状态字段、页码冲突、截断 |
| `rulesVersion` | `k1` |

### 4.2 证据校验

- 引文必须逐字出现在**本次发送的对应段落**里（空白折叠后比较）；否则拒绝并计数。
- 模型的 `passageId` 必须存在；模型若给了 `page`，必须等于该段落记录的页码，否则 `wrong-page` 拒绝（页码本身永远取自服务端记录）。
- `support: direct` 但没有任何通过校验的引文时，**降级为 `inferred`** 并显示警告，而不是保留“原文直接支持”的假象。
- 引文逐字匹配只证明文字存在；界面明确写出它**不证明关系的学术正确性**。

### 4.3 方向与类型

- `prerequisite`：`from` 需要先理解 `to`，方向 `from-first`。
- `extends`：`from` 扩展了 `to`，方向 `from-first`。
- `related`：无方向，`undirected`。
- 模型必须给出 `direction`；与类型不一致即 `relation-direction` 拒绝。缺省时按类型补全并计数，不静默接受矛盾。
- 服务端用已有关系 + 本批已接受关系做前置环检测；浏览器领域层 `mergeSuggestions` 再做一次，确认时第三次检查。

### 4.4 模型不能写入的东西

服务端会统计并忽略模型返回的 `id`、`status`、`confirmed`、`confidence`、`doi`、`arxivId`、`paperId` 等字段，并在响应中提示。浏览器 reducer 无论收到什么，都强制 `status: suggested`、`origin: ai`。真实模型若试图“直接确认”，不会生效。

## 五、Task B：受控的论文上下文检索

### 5.1 提取与扫描

- `extractPageText` 用 pdf.js 文本层提取，不渲染页面；失败页单独记录，不当作空页。
- `pagesToScan` 的优先级：当前页 → 前后 4 页 → 前 12 页 → 有笔记/难点的页 → 其余页；总上限 **48 页**。未扫描页数写入计划。
- 当前页优先使用阅读器已渲染的文字层（与读者看到的一致）。

### 5.2 评分与选段

- 词项来自选中文字 + 当前项目概念名称/别名；去停用词，最多 10 个词项。
- 页面得分 = 词项词频 × IDF + 定义句式数 × 1.5 + 当前页/邻近页加权。
- 最多选 3 个额外页面；每页取最佳定义/术语句附近 1–3 句，单段 ≤1200 字。
- 选中的原文 + 本页上下文单独成段；笔记和难点建议可作为额外段。
- 去重（相同前缀/被更长段包含）、按相关性排序、总字符上限 **6000**。
- 计划显示：页码、段落来源、理由、字数、是否截断、是否碎片化、扫描页数、失败页、未扫描页数、是否在线/是否收费。

### 5.3 公式与多栏

- 文字层中单字符 item 占比 ≥45% 且 item 数 ≥8 时标记为碎片化；计划明确说模型只看到碎片。
- 提示词要求公式碎片按原样引用；模型补写的 LaTeX 只能写在 `explanation` 里，并注明是模型解释；界面再次提示“模型补写的公式不是 PDF 原文”。
- 本轮没有引入整页版面重排；当前页已有的 Phase 5 版面提示仍用于 ask 流程，知识计划的额外页使用 PDF 提取顺序并明确标注这是提取文字。

### 5.4 本轮实际计划示例

真实扩散语言模型论文第 2 页，选中 193 字：

```
使用第 2、3、14、16 页 · 4 段 · 1834 字 · 未截断
第 2 页 · 读者选中的原文 · 893 字 · 选中的原文及本页上下文
第 14 页 · 术语出现的位置 · 266 字 · 包含检索词
第 16 页 · 术语出现的位置 · 311 字 · 包含检索词
第 3 页 · 术语出现的位置 · 364 字 · 包含检索词
```

三页额外上下文均来自本论文，逐页列出；没有发送整篇论文。

## 六、Task C：确认机制与学习路径

### 6.1 建议与正式知识分离

- `mergeSuggestions`（领域层）是唯一的建议入口：
  - 同名/别名概念 → 复用已有稳定 ID，不覆盖摘要、状态或项目链接；
  - 重复关系（`related` 双向）→ 跳过并报告原因；
  - 会形成循环的前置关系 → 跳过并报告原因；
  - 建议证据 ID 冲突、出处重复 → 跳过；
  - 关系没被加入时，它的证据一并跳过；
  - 所有新增记录强制 `suggested / ai`，证据强制 `source: ai`。
- 返回 `SuggestionReport`：新增/复用数量与逐条跳过原因。界面显示「有 N 条内容没有加入知识库（重复、循环或引用不成立）」。

### 6.2 确认、拒绝、改类型

- 采纳概念 → `confirmConcept`；采纳关系 → `confirmRelationChecked`（再次检查重复/循环，失败时显示原因）。
- 忽略关系 → 删除关系及其专属证据；概念与论文不受影响。
- 忽略概念 → 删除概念、它的证据和关系；如果它已经用在**确认过的关系**里，界面禁用「忽略」并说明先处理那些关系，避免误删已确认知识。
- 修改关系类型 → `updateRelationKind`，重新检查重复/循环；建议态和已确认态都可改。
- 新概念可加入当前项目；在概念详情里可加入任何其他项目。

### 6.3 学习路径

`learningPath` 只遍历**已确认**的 `prerequisite` 边，计算从当前概念可达的前置子图，按最长深度排序（基础在前），同层按名称稳定排序，当前概念最后。最多 12 个节点、深度 8；循环数据不会导致无限遍历。

示例（真实验收中确认的关系）：

```
模拟概念 B → 模拟概念 A
```

概念详情显示编号路径；阅读器本地知识卡也显示路径，点击可跳到知识视图。路径明确标注「只使用你确认过的前置关系」「同层分支不代表唯一正确顺序」。

## 八、Task E：持久化、迁移与备份

### 8.1 数据完整性

- 建议与正式知识通过 `status` 分离；`mergeSuggestions` 从入口强制。
- 概念 ID 稳定；名称/别名匹配只用于复用，不合并。
- 论文身份与 PDF 哈希分离：证据记录 `paperId` + `pdfSha256`；替换 PDF 后 `isStaleEvidence` 判定为旧文件，跳转禁用。
- 关系证据可追溯到论文、文件、页码、原文、验证级别。
- 用户确认的内容不被重新分析覆盖：同名概念复用；重复关系跳过；确认状态不由模型写入。
- 删除项目只调用 `project/detach`，共享概念保留。
- 删除概念会清理它的证据和关系；删除关系会清理关系专属证据。

### 8.2 备份兼容

- 知识 `version` 仍为 1；备份 `formatVersion` 仍为 1；`app.knowledgeVersion` 仍为 1。
- 旧 payload 没有 `support/rationale/relationId/verification` 时照常读取。
- 严格解析新增交叉引用检查：`evidence.relationId` 必须指向存在的关系；`relation.evidenceIds` 必须指向存在的证据，且来源概念一致。
- 恢复时：
  - 被跳过的关系（例如循环）会使它的证据降级为概念证据（清空 `relationId`），不丢原文；
  - 丢失的论文/证据不会留下悬空链接；
  - 同 id 关系的新字段参与冲突比较；
  - 前置循环检查现在覆盖建议态关系。
- 真实浏览器链：
  1. 浏览器 A 建立 Phase 7 形状工作区（项目 + 真实 PDF + 手工概念），导出旧备份；文件中没有任何 Phase 8 字段；
  2. 全新浏览器 B 恢复旧备份 → 在真实论文上分析 → 接受概念/关系 → 加入第二篇真实论文 → 导出新备份；
  3. 全新浏览器 C 恢复新备份 → 支持类型、解释、关系证据、学习路径、两篇论文的出处全部保留，跨文献跳转仍准确。
- 新备份实际计数：`projects 1 / papers 3 / concepts 3 / evidence 4 / relations 2`（papers 中有一个项目创建时的核心占位记录）。

## 十、本轮发现并修复的缺陷

1. **忽略关系后，建议行错误地挂到同一对概念的另一个已确认关系上。** 复现于 `05-accepted-learning-path.png` 的早期运行：被忽略的 B→A「相关」行显示成 A→B「前置知识 / 已采纳」。修复：用模型解释作为该建议的稳定指纹匹配存储关系；说明不匹配时不再回退到任意同端点关系。新增单元测试覆盖。
2. **忽略建议概念会连带删除已确认关系。** 建议概念 B 被 A→B 确认关系引用时，删除 B 会删除关系。修复：界面在该情况下禁用「忽略」，说明先处理关系；测试验证。
3. **第二篇论文无法给已有概念增加出处。** 服务端匹配到已有概念时直接丢弃该条建议的证据，导致跨文献导航缺一条出处。修复：已有概念仍返回 `existing:true` 的条目和通过校验的证据，浏览器把证据挂到既有稳定 ID；不重复创建概念。
4. **关系证据被当成概念证据重复显示。** 本地知识卡把关系证据也列进概念的出处，出现两条相同引文。修复：概念出处只取 `relationId === undefined`；关系证据显示在关系建议行内。
5. **Mock 引文从单词中间开始。** 由于选段从选中文字前 350 字开始，Mock 取第一句会得到 `vity to prompt...`。修复：Mock 优先引用读者的实际选中文字，次要引文只取以大写/数字开头的完整句。
6. **领域层旧入口只按 id 去重。** `suggestions/add` 原实现会让同一关系以不同 id 重复进入图谱。修复：统一走 `mergeSuggestions`，重复概念复用、重复关系/循环/悬空证据全部跳过并报告。
7. **确认关系时没有再次检查循环。** 建议提出后图谱可能变化。修复：`confirmRelationChecked` 在确认时重新检查重复/循环；界面显示拒绝原因。
8. **删除关系/概念留下关系专属证据。** 修复：`deleteRelation` 删除其证据；`deleteConcept` 删除所有涉及它的关系证据（包括它是目标概念的关系）。
9. **上下文计划可能超过服务端 6 页上限。** 笔记/难点来自多个不同页时，计划可能超过服务端约束。修复：计划阶段按页上限截断并提示「一次最多分析 6 页」。
10. **无选区且当前页无文字时可能没有 selection 段。** 修复：使用第一篇有文字的页作为主段，并在计划中说明。
11. **分析完成后侧栏仍停在顶部。** 修复：结果出现后自动滚动到结果区。
12. **新增的无障碍标签与旧「关系类型」选择器冲突。** `getByLabel('关系类型')` 同时命中「修改 X 的关系类型」。修复：新选择器标签改为「把与 X 的关系改为 / 改为哪种关系」，既避免歧义也更易读。
13. **回归脚本选择器受学习路径影响。** 概念详情现在会在前置列表和学习路径重复同一名称按钮，`getByRole` 严格模式命中多个。修复：脚本对确认前置按钮使用 `.first()`；这是测试选择器更新，不是产品缺陷。
14. **跨文献证据丢失的边界（第 3 条的同一个缺陷）在备份中也可能表现为悬空链接。** 严格解析新增交叉引用检查；恢复时被跳过关系的证据降级为概念证据，不丢原文。

## 十一、已知限制

1. **真实模型能力未验证。** 本轮只验证协议、证据约束、确认流程、持久化和界面；概念质量与关系学术正确性必须在获得授权的真实联调中评估。
2. **检索是词项级、非语义的。** 同义词、跨语言术语、深层概念关联可能召回不足；没有 embedding/向量库，这是本轮明确的取舍。
3. **最多扫描 48 页、发送 6 页/6000 字。** 超过的部分会在计划中说明未发送；对超长论文的召回质量未验证。
4. **额外页使用 PDF 提取顺序。** 当前页有 Phase 5 的版面测量；其他页没有做整页多栏重排，只在计划中说明这是提取文字。
5. **公式仍是文字层碎片。** 系统不拼造公式；模型补写的 LaTeX 只作为模型解释显示，不进入引用校验。
6. **关系方向只能做结构校验。** 服务端能发现「类型与 direction 字段矛盾」，不能判断模型把学术依赖方向理解反了；读者仍需自己判断并采纳。
7. **证据位置验证分级。** 当前页可定位时标 `located` 并保存框；其他页只做服务端逐字校验（`verbatim`），跳转时再尝试匹配，失败会明确说明。
8. **备份不加密。** 与 Phase 7 相同；建议条目、解释和引文会随备份一起导出。
9. **Mock 结果不是学术结论。** 概念名固定为「模拟概念 A/B」，只用于端到端数据流。
10. **没有实现「只恢复某个项目」。** 仍为整库恢复（Phase 7 限制）。
11. **没有自动清理孤立 PDF blob。** 同 Phase 7。
12. **阅读器知识面板与 AI 助手是两个独立会话。** 关闭阅读器后不保留对话/建议会话；建议一旦加入知识库则持久化。

## 十四、下一步：真实模型联调计划（独立审批，本轮未执行）

> 在用户另行批准之前不运行。以下为计划，不是已发生的结果。

### 14.1 目标与范围

验证真实 DeepSeek Flash 在**同一协议**下的：

1. 是否能提出可用的概念与关系；
2. 引文是否倾向于逐字复制（以及失败率）；
3. `support` 分类是否诚实（direct / inferred / external）；
4. 方向是否与类型一致；
5. 在 6000 字上下文内是否足够；
6. 输出长度、延迟、成本。

不验证：学术正确性的黄金标准（没有人工标注集）；跨 10 篇以上论文的规模化。

### 14.2 模型与参数

| 项 | 值 |
| --- | --- |
| Provider | `deepseek` |
| 模型 | `deepseek-flash`（当前配置默认） |
| 端点 | `https://api.deepseek.com`（服务端环境变量，浏览器不可改） |
| 思考模式 | 第一轮 `DEEPSEEK_THINKING=disabled`（先测非思考，成本可控）；若引文/方向质量不足，第二轮再测 `low` |
| 输出上限 | `AI_MAX_OUTPUT_TOKENS=8192`（与当前默认一致） |
| 超时 | `AI_TIMEOUT_MS=120000` |
| 速率/并发 | 保持 `30/min`、`4` 并发；联调实际远低于上限 |
| 密钥 | 只从服务进程环境变量读取；不写入浏览器、不写入备份、不写入报告 |

### 14.3 请求预算

| 阶段 | 请求数 | 内容 |
| --- | --- | --- |
| 冒烟 | 1 | 1 篇真实论文、1 个选区、最多 4 段 |
| 主场景 | 4 | 两篇真实论文 × 2 个不同选区（定义段/方法段） |
| 稳定性 | 2 | 同一选区重复一次（验证去重）；换一个相邻页再分析 |
| 边界 | 3 | 极小选区（短于 80 字）、公式碎片选区、跨页/多栏页 |
| 失败观察 | 2 | 故意用很短的上下文（只 1 段）观察 `groundedInText:false` 与建议数量 |
| **合计上限** | **12** | 不含健康检查；任何情况下不超过 12 次业务请求 |

输入预算：每次 ≤9000 字（约 3k tokens），12 次 ≤36k tokens（不含系统提示）。输出预算：每次 ≤8192 tokens，12 次 ≤98k tokens；预计实际输出 800–2500 tokens/次。

成本预算：按 DeepSeek 官方当前价目表结算；**总支出硬上限设为 ¥2 或 12 次请求，先到者停止**。若账户显示余额不足，立即停止。报告只记录 token 数与官方账单截图/数字，不记录密钥。

### 14.4 上下文与数据

### 14.5 停止条件

1. 12 次业务请求用完；
2. 总支出达到 ¥2；
3. 出现 `auth`、`insufficient-balance`、连续 3 次 `upstream`/`timeout`；

7. 用户要求停止。

## 十五、Agent 执行效率复盘

- **先协议、后界面**：服务端反例表先于 UI 完成，浏览器验收只需要验证“界面是否如实显示这些结果”。
- **领域层兜底**：服务端、`mergeSuggestions`、确认时三层检查，使“模型试图写 confirmed”在任何入口都无效。
- **计划即请求**：界面展示的上下文计划和实际发送的段落由同一个 `RetrievalPlan` 生成，验收能逐项核对。
- **真实产物链路**：旧备份导出、恢复、分析、再导出、全新恢复，全程使用真实 PDF 与真实下载文件，没有复制存储目录。
- **失败先于成功被看到**：跨文献证据、忽略后误挂、概念删除连带关系，都是浏览器验收暴露的真实缺陷，而不是单元测试构造出来的。

**代价较高的部分**

- **选择器歧义**：新增的学习路径和“关系类型”标签让旧脚本的严格选择器命中多个元素；修复过程中确认了两处是产品可访问性问题（标签应更具体），一处是测试选择器应 `.first()`。
- **Mock 引文质量**：选段从选区前 350 字开始，Mock 取第一句会从单词中间开始；这也提醒真实模型可能引用边界碎片，因此保留服务端逐字校验和 UI 的“位置未核实”分级。
- **备份测试的时间成本**：三环境链（旧备份→分析→新备份→全新恢复）比单环境慢得多，但它直接覆盖了本轮最危险的兼容性要求。

**总体**：本轮新增约 8,500 行（含测试、验收脚本、样式与报告数据采集），`check`、构建、48 项 Phase 8 验收与 263 项回归全部通过。主要调试集中在 UI 选择器、跨文献证据映射与建议-存储关系匹配，而不是协议或备份格式本身。
