### 2.4 「提取文本与视觉显示不一致」这一条怎么验的

这是 2.3 第 4 项。做法是：对每个文字层 span，把它在页面上的框换算到画布像素坐标，直接读那块像素，问「这里到底有没有画出东西」。**提取文本漂移到别处**——也就是会让所有高亮落到错字上的那类故障——只有在这里才现形，因为 span 下方会变成空白。两篇论文、两个不同页面、131 个 span，全部通过。

反方向（画面上有字、提取不出来）由第 8 项覆盖：全文扫描没有发现未映射字形，也没有空白页。

**这是「生成样本」永远给不了的证据**：生成的 PDF 由我们决定怎么排版、用什么字体，它通过说明不了真实论文能通过。

## 三、Task B：AI Provider 与安全调用架构

### 3.1 分层

```
浏览器（src/services/ai/）
  client.ts    只发结构化请求；无 Authorization、无 Key、无端点
  context.ts   把当前页的文字切成「选中的原文 + 同页前后文」，纯函数
  render.ts    把回答当作纯文本切段，只把**已校验**的编号变成可点的引用
        │  POST /api/ai/ask（同源，经 Vite 代理）
        ▼
本地服务（server/，仅监听 127.0.0.1）
  guards.mjs   Host / Origin / 路径 / 方法 / 体积 / 频率 / 并发
  prompt.mjs   输入校验 + **组装提示词**（系统消息由常量写成）
  providers/   Provider Adapter：deepseek.mjs（官方协议）| mock.mjs（离线）
  citations.mjs 引用校验：段落 id 必须是我们发出去的，引文必须逐字
  log.mjs      只记方法/路径/状态/耗时/段落数/字符数
```

**Key 只存在于服务进程的环境变量里**，前端源码、打包产物、Git 历史里都没有。实测：把 `dist/` 的入口与全部 JS 打包产物（**738 KB**）连起来搜，`DEEPSEEK_API_KEY`、`sk-…`、`api.deepseek.com` **一个都没有**。

### 3.2 两道门，防止"启动即计费"

`AI_PROVIDER` 默认是 `mock`。要走在线模型必须**同时**：

```bash
AI_PROVIDER=deepseek DEEPSEEK_API_KEY=sk-… npm run ai:serve
```

只设 Key 不生效。**本轮全程没有设置这两项**，所以没有产生任何在线调用。

### 3.3 官方协议核对

按要求核对了 DeepSeek 当前官方文档（`api-docs.deepseek.com`），没有沿用记忆里的旧别名：

- `POST https://api.deepseek.com/chat/completions`，`Authorization: Bearer …`
- 当前型号名：**`deepseek-flash`**、`deepseek-v4-pro`（旧名 `deepseek-v4-flash` 已退役但仍被接受）
- 在线提供方以 `response_format: {"type":"json_object"}` 请求，因为引用校验需要可解析的结构
- `finish_reason === 'length'` 会被翻成「回答被截断」，不当作完整回答展示

应用**没有锁死在某一个模型**：`DEEPSEEK_MODEL` 可配置，只是会校验成安全标识符。

### 3.4 边界（都有实测或单测）

| 要求                       | 实现                                               | 证据                                                                                                                     |
| -------------------------- | -------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------ |
| 只监听 127.0.0.1           | 常量，**不可配置**（连"改错环境变量"这条路都没留） | 单测断言配置对象里没有 host 字段                                                                                         |
| Origin 约束                | 回环来源始终允许；其他必须显式列出                 | 服务端实测：`https://evil.example` → **403**                                                                             |
| Host 约束（DNS rebinding） | 必须是回环地址                                     | 用原始 socket 发 `Host: evil.example` → **403**                                                                          |
| 不是任意转发代理           | 只有 `/api/ai/health` 与 `/api/ai/ask`，其余 404   | 实测 `/api/ai/not-a-real-endpoint` → **404**                                                                             |
| 请求大小                   | 256 KB，边收边判，超出即停                         | 实测 300 KB → **413**；不是 JSON → 400                                                                                   |
| 频率与并发                 | 30 次/分、最多 4 个在途                            | 实测第 31 次 → **429**；第 5 个并发 → **429 busy**                                                                       |
| 提供方不可由请求指定       | 端点/模型/凭据全部来自进程环境                     | deepseek 适配器单测：请求体里不含任何 URL                                                                                |
| 不记录密钥与正文           | 日志接口只接受固定字段，没有自由文本入口           | 实测整轮日志里没有 Key、没有被选中的论文文字                                                                             |
| 超时与取消                 | 服务端 60 s，客户端 60 s，页面关闭即中止上游       | 单测覆盖 timeout / cancel / network / 401 / 402 / 429 / 5xx，并断言错误信息里不含 Key 与上游正文                         |
| 模型输出不得当 HTML 执行   | 回答只作为文本渲染，从不 `dangerouslySetInnerHTML` | 实测：回答里的 `<img onerror>` 与 `<script>` 原样显示，`window.__aiInjected` 仍为 `undefined`，DOM 里没有 `img`/`script` |
| 不自动上传整篇 PDF         | 上下文只由阅读器当前页的文字构成                   | 实测：1134 字、3 段、全部第 1 页；**第 2 页的文字一个字都没进请求**                                                      |

### 3.5 PDF 原文作为不可信数据

这一条是**结构上**保证的，不是靠提示词请求模型配合：

1. **系统消息由服务端从常量组装**，论文文本永远不进入 `system`。
2. 页面送来的内容只作为 `user` 消息，且被夹在 `<paper_text> … </paper_text>` 之间。
3. 文本里出现的分隔符会被**消解**（`<paper_text>` → `[paper_text]`），论文无法提前闭合数据块。
4. 页面**没有能力**提供系统消息：请求类型里根本没有这个字段。

**最强的证据是一条可证伪的不变量断言**：把一段普通论文和一段满是越狱指令的论文分别走一遍，
`buildMessages(...).system` **逐字节相同**；并且系统消息里不含论文标题、正文、提问或排版提示的**任何片段**（单测覆盖六个片段）。

浏览器端的对应实测（`[[mock:html]]` 之外还有一个专门的注入样本 PDF）：

- 夹带指令的文字**只出现在 `passages` 里**，请求体里没有 `system`、没有伪造的 role；
- 回来的回答是 mock 自己那套固定框架，不是文档要求的那个词；
- 回答里的 `<script>` 被当作纯文本。

**诚实地说**：mock provider 不会听任何指令，所以浏览器端**证明不了真实模型会抵抗注入**。它能证明的是「原文被当作数据运送、模型输出被当作文本显示」这条链路成立；「真实模型是否照做」属于未验证，见第八节。

## 四、Task C：上下文构造与引用校验

### 4.1 送什么，以及怎么让用户看见

`buildAskContext` 是纯函数：输入是**阅读器当前页的渲染文本**加上选区的起止下标，输出是

```
selection  读者选中的原文（主证据）
before     同页上文，最多 900 字
after      同页下文，最多 900 字
```

- 从不跨页、从不跨论文。服务端上限：单段 2000 字、合计 6000 字、最多 8 段。
- 面板里有一个「查看会发送的范围」折叠区，**展开后能看到逐字的原文范围**和字数统计，例如
  「选中 247 字；同页上文 85 字；同页下文 191 字；合计 523 字」。实测展开可见。
- 用的是**渲染出来的文字层**（和锚点同一份文本），所以模型看到的不会超出读者能看到的东西。

### 4.2 多栏文本：检查，然后如实报告

`src/features/reader/layout.ts`（本轮新增）从**几何**重建阅读顺序：

1. 先用 span 的水平中心找出分栏位置（页宽 20% 以上的空档，两侧各有 ≥3 行）；
2. 然后在**每一栏内部**按纵向聚成行（容差半行高，所以上标不会被拆成另一行）；
3. 每行按左边界排序，得到「哪一栏 → 哪一行 → 行内第几个」的阅读序键；
4. 数一数**相邻两个 span 在提取顺序里逆序**的次数。

逆序占比超过 10% 就判定提取顺序不可信，并**明确告诉用户和模型**：

> 这一页的文字提取顺序与版面顺序不一致（很可能是多栏排版），下面提供的上下文顺序可能与阅读顺序不同。

顺带说清一件事：**这是检查与告知，不是重排。** 顺序可疑时应用**仍然按提取顺序发送**，只是把风险说出来。理由是重排会同时破坏锚点与选区的一致性（Phase 3 的锚点就建立在渲染顺序上），而"说不知道"永远优于"猜错了还很自信"。

### 4.3 引用校验：页码从不采信模型

模型被要求输出：

```json
{
  "answer": "…… [1] ……",
  "groundedInText": true,
  "citations": [{ "n": 1, "passageId": "selection", "quote": "逐字来自该段" }]
}
```

服务端逐条校验，**任何一条不合格就丢弃并计数**：

| 规则                                                 | 处理                                             |
| ---------------------------------------------------- | ------------------------------------------------ |
| `passageId` 必须是**本次发出去的**段落之一           | 否则丢弃                                         |
| `quote` 必须是该段落**逐字的子串**（空白折叠后比较） | 否则丢弃——改写、拼接、编造一律不认               |
| 编号重复 / 越界                                      | 丢弃                                             |
| 页码                                                 | **完全不读模型给的页码**，取服务端自己的段落记录 |

回答正文里引用了没有通过校验的编号时，会提示「这些标记已按普通文字显示」——`[7]` 就只是 `[7]`，不会变成按钮。模型没按 JSON 返回时，整段降级为纯文本回答、零引用，并说明原因。

实测：mock 故意返回一条编造的引文和一条不存在的段落 id，界面只保留了唯一通过校验的那条，并显示「有 2 条引用未通过校验（引文与提供的原文不符），已丢弃」。

## 五、Task D / E / F：使用流程

### 5.1 入口（克制）

选中原文后，浮动工具条上多了一个 **AI** 按钮，点开是一张短菜单：

```
解释这段话 / 逐步讲解原理 / 解释数学公式 / 翻译为中文 / [针对这段原文提问…]
```

没有多一层套一层，也没有新增一排常驻按钮。菜单里的模式与 `server/prompt.mjs` 里的一一对应。

### 5.2 每种模式的回答形态

| 模式         | 对模型的要求                                                                                      | 界面                                       |
| ------------ | ------------------------------------------------------------------------------------------------- | ------------------------------------------ |
| 解释这段话   | 先说作者在说什么，再交代背景、符号与逻辑关系                                                      | 面板正文                                   |
| 逐步讲解原理 | 按步骤说清"在做什么、为什么、依赖什么前提"                                                        | 面板正文                                   |
| 解释数学公式 | 逐个说明变量、前提、推导步骤；公式写在 `$…$` 里；**提取残缺的公式必须直说，不得补写成确定的原文** | 面板正文                                   |
| 翻译为中文   | 忠实原意，保留术语与符号；只翻译不扩写                                                            | 英文原文与中文译文**上下对照**，译文可折叠 |
| 自由提问     | 围绕选中原文回答                                                                                  | 面板正文 + 继续追问输入框                  |

贯穿所有模式的硬性规则写在系统消息里：区分「原文明确说明」与「AI 补充解释」；依据不足直说；
遇到提取缺字或乱码要指出来；不输出 HTML。

模型对「依据是否充分」的自我判断（`groundedInText`）会以提示条显示，**并明确标注这是模型的判断**，不是被验证过的事实。

### 5.3 回答与原文的联动（Task E）

- 回答下方与正文里都列出引用，每条都带**第几页**和原文字段。
- 点引用 → 滚动到该页 → 用文字的匹配找出引用文字的位置 → 用**独立图层**（`data-spotlight`，空心描边，与批注高亮外观完全不同）短暂标出。
  - 实测：标出的位置与重新选中同一段文字的浏览器框 **误差 0.0px**。
  - **定位不到或出现多次时沿用 Phase 3 的规则**：分别提示「这段引文没有在这一页的文字里找到」/「这段原文在这一页出现了多次，无法确定引用的是哪一处」，绝不错标。
- **保存为笔记**：复用既有 Annotation 与持久化机制，anchor 就是这次选区的那份（同一文件、同一页、同一组框）。
- **AI 内容可区分、不覆盖手写笔记**：schema 升到 **v5**，`origin: 'user' | 'assistant'` 与 `sourceLabel`。保存的笔记在面板里带「AI 辅助」徽标；`applyAnnotationEdit` 只改 note/kind，**从不改 origin**，所以读者改过之后仍然看得出它起点是 AI。保存永远**新增**一条，不修改任何已有笔记。
- **默认不保存对话**：会话只在内存里。实测「提问之后 localStorage 里没有多出任何东西，也不含回答文字」。
- **失败不影响已有数据**：模型出错时面板显示错误与「重试」，实测此时笔记条数不变、高亮仍在、阅读位置不动。

### 5.4 中英对照（Task F，最小实现）

只做**选中段落**的对照，明确不做整篇翻译。左侧（上方）是读者选中的英文原文，下方是中文译文，各有标题；「隐藏译文」可以折叠，折叠后原文仍在。实测：原文 26 字中被完整显示 21 字（其余是空白折叠），译文 151 字；折叠后回答正文消失而 `.ai-original` 仍在。PDF 文件本身从不被修改。

### 7.2 我自己写错的东西（如实记账）

这一轮我在**验收脚本**上犯的错比在应用代码上多，逐条列出：

1. **截图路径用 `new URL(...).pathname.slice(1)`**：项目路径含中文，URL 编码后变成 `D:/%E8%AE%BA…`，Windows 把它当成绝对路径，**7 张截图被写到 `D:\%E8%AE%BA…\` 去了**（项目之外）。是"截图目录是空的"暴露的。已改用仓库统一的 `fileURLToPath`，并把误写的目录清理掉。
2. **`relativeBoxes` 三处漏写 `await`**：先表现为一个莫名其妙的 "Target page, context or browser has been closed"（浏览器关闭时未 await 的 promise 才 reject），补上 `before` 的 await 后又变成 `after.length === undefined`。两次都是我的错，不是浏览器的错。
3. **验收脚本挑错了论文**：`createProject` 本身会创建一篇核心论文，所以 `papers[0]` 不是导入的那篇；改成"第一篇带文件的"之后，第二篇又变成第一篇。最终改为**按阅读器标题匹配**当前打开的那篇。
4. **"跨栏选区"用例按 span 下标选**：真实论文的提取顺序不保证一栏连续，结果选出来的框横跨两栏（占页宽 88%）——那是在量一个跨了栏沟的选区。改成**按几何挑出「连续且全在左半页」的区段**。
5. **"选区是连续散文"用了 ≥10 词的任意门槛**：那是照着生成样本调出来的数，第二篇真实论文只有 8 词就挂了。换成真正的不变量：**应用捕获的文本 == 浏览器报告的选文**。
6. **注入用例一开始断言"回答里不含 PWNED"**：mock 会把选中的原文**引用**在回答里，`PWNED` 自然出现。这不是模型服从，是我把"引用了危险文字"当成了"执行了危险指令"。改成断言"回答是 provider 自己那套框架、且没有回显系统提示词"。
7. 若干次比较口径写错（trim 过的引文 vs 没 trim 的段落、按视口坐标比较跨刷新位置），都在当轮改成了同类可比的口径。

## 八、API 联调是否真实完成

**没有完成，这一点不含糊。**

- 本轮**没有拿到任何 DeepSeek 凭据，也没有获得调用授权**，因此**没有向在线模型发出过一次请求**，没有产生任何费用。
- 因此第二轮交付目标只能宣布为：**Mock 模式闭环通过。** 不能宣称"真实在线答疑已完成"。
- `server/providers/deepseek.mjs` 的**协议层是单测覆盖的**：用注入的 `fetchImpl` 断言了 URL（`{base}/chat/completions`）、`Authorization: Bearer`、`model`、`stream:false`、`response_format`、系统消息位置、`choices[0].message.content` 解析、`finish_reason === 'length'` 的截断标记，以及 401/402/403/429/500/503 各自的错误分类、超时、调用方取消、非 JSON 回包、无内容回包。也断言了**抛出的错误里不含 Key、不含上游回包正文**。
- 但**协议正确 ≠ 联调成功**。真实调用可能暴露的东西（真实限流行为、真实的中文回答质量、真实延迟下的超时设置是否合适、真实 JSON 模式的遵循度）本轮**一件都没有验证**。
- 联调步骤已写在 `server/README.md`：设好两个环境变量、`npm run ai:serve`，面板顶部会显示「回答来自 DeepSeek …：会调用在线模型，可能产生费用」。

## 十、未解决的技术限制

1. **真实 API 未联调**（见第八节）。这是本轮最大的一条。
2. **没有流式输出**：回答一次性返回。长回答期间只能看到"正在请求模型…"和取消按钮。
3. **公式只按文本展示**：LaTeX 以 `$…$` 的原文呈现，没有接 KaTeX/MathJax（那是体积不小的运行时依赖）。模型写错 LaTeX 时读者看到的就是错的写法。
4. **对话不持久化**：关闭面板即失去本次对话。这是刻意的（避免无意义的数据膨胀），但也就没有"导出这次对话"。
5. **真实论文样本只有两篇**：都是英文、双栏、LaTeX 排版的 AI/CS 论文。中文论文、扫描版、超长（几百页）、表格极密集的论文**未验证**。
6. **多栏只检查不重排**：顺序可疑时仍然按提取顺序发送，只是明确提示。真正的阅读序重建没做。
7. **`groundedInText` 是模型的自我判断**，界面照实转述并标注来源，但**没有被验证**——它可能是错的。
8. **不接受跨页选区的提问**（沿用 Phase 3 的拒绝规则），跨页批注仍未做。
9. **OCR 仍不在范围内**：扫描页无法提问，也无法高亮。
10. **引用定位依赖文字匹配**：引用文字在页面上重复出现时会报"无法确定"，而不是跳到某一处——这是刻意的，但确实会让一部分引用点不过去。
11. **本地服务需要用户自己启动**（`npm run ai:serve`）。没有自动拉起，没启动时面板只说明"还没有连上本地 AI 服务"。
12. **面板是互斥的**：笔记与 AI 答疑占同一列，一次只能开一个。
13. **批注仍存在 LocalStorage 主文档里**（Phase 3 遗留），AI 笔记写的是同一个地方；数万条量级需要迁 IndexedDB。
14. **Tauri 未接入**（本轮禁止项）。

## 十一、Agent 执行效率复盘

口径同前：拿不到 token 用量与账单，下面只描述可观察的工作构成，不含任何 token/费用估算。本轮未调用其他 AI 模型或子代理。

**有效开发**：新增 46 个文件。核心决策只有四个：**Key 不进浏览器**（本地回环服务持有凭据与协议）、**两道门才允许在线调用**（默认离线 mock）、**系统消息由服务端从常量组装、论文文本只进数据块**（PDF 是数据不是指令）、**引用一律拿自己发出去的段落校验、页码从不采信模型**。

**测试与验收**：单测全量 3 次；`npm run check` 5 次；`npm run build` 约 8 次；`verify:ai` 跑了 **8 轮**才全绿，`verify:real` 跑了 **5 轮**。每一轮都有新的诊断输出（请求体、几何偏差、计算后的背景色链、页面上实际的元素状态），没有"同样失败重跑"。

**重复与低效操作（如实列出）**：

1. **有 5 条检查是我把断言写错了**，其中 3 条（截图路径、漏 await、挑错论文）让我多跑了 3 轮；截图那条最亏——它把文件写到了项目外面，直到我"按计划去看截图"时才发现目录是空的。
