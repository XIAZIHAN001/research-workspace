## 三、Task A：知识建议拒绝与恢复

### 3.1 两种行为被明确分开

| 操作 | 数据效果 | 下次分析 |
| --- | --- | --- |
| 暂时忽略 | 删除当前建议关系及其证据，不记录决定 | 同一建议可以再次出现 |
| 拒绝该关系 | 删除当前建议，并写入一条 `RejectedRelationSuggestion` | 同一主张不会自动恢复，直到读者撤销拒绝 |

界面文案与按钮已区分：关系建议行同时显示“拒绝该关系”和“暂时忽略”，后者 title 说明“只移除本次建议；下次分析可能再次出现”。已确认的关系行不再显示这两个操作，避免把正式知识当作建议删掉。

### 3.2 拒绝记录的身份

```ts
interface RejectedRelationSuggestion {
  id: string;
  from: string; // 稳定概念 id
  to: string;
  kind: RelationKind;
  rationale: string;
  evidence: { paperId; pdfSha256; page; quote }[];
  fingerprint: string; // rel1-<16 hex>
  provider?; providerLabel?; model?; rulesVersion?;
  createdAt; updatedAt;
}
```

`fingerprint` 只由以下字段决定：

- 两个稳定概念 id（不是名称，也不是每次运行的建议 id）；
- 关系类型；
- 规范化后的解释文本（空白折叠、大小写不敏感）；
- 证据集合（paperId、文件哈希、页码、规范化引文；顺序无关）。

因此：

- 同一主张在不同分析轮次中即使生成全新的建议 id，指纹不变；
- 换一种解释、换一组证据、换一种关系类型，都是新主张，可以作为新建议出现；
- 模型或提供商变化不改变指纹；
- 记录中仍保留解释和证据快照，读者在“已拒绝”区域能看到当初拒绝的是什么。

### 3.3 审查与恢复位置

- 阅读器知识面板：建议行可“拒绝该关系”/“暂时忽略”；结果区下方有“已拒绝的关系建议”，可“撤销拒绝”。
- 知识视图概念详情：该概念相关的拒绝记录单独成块，显示类型、另一端概念、当时解释、证据条数，并可撤销。
- 撤销只删除拒绝记录，不自动恢复旧建议；下一次分析可以再次提出。这是有意的：撤销的是“拒绝决定”，不是“重新采纳”。

### 3.4 已确认关系不会被覆盖

- `rejectRelationSuggestion` 对 `status: confirmed` 直接拒绝，返回“已确认的关系不能被当作建议拒绝”。
- `mergeSuggestions` 仍先检查已存在关系，重复建议跳过；拒绝表不会删除或修改任何已确认关系。
- 浏览器工作流断言：采纳后的 AI 关系在再次分析后保持同一 id、同一 kind、同一 `updatedAt`、`status=confirmed`。

### 3.5 测试

单元/领域测试覆盖：

- 指纹对建议 id 不敏感、对证据顺序不敏感，对 kind/解释/证据/端点敏感；
- 拒绝删除建议与证据、保留概念；
- 同主张换 id 重放仍被跳过；
- 不同解释、不同证据、不同 kind 可以重新出现；
- 撤销后同主张恢复；
- 确认关系不能被拒绝；
- 删除概念会删除相关拒绝；合并概念会重映射拒绝端点并重算指纹；
- 严格解析器拒绝指向不存在概念的拒绝记录；
- 备份合并会重算指纹并保留拒绝。

## 四、Task B：知识数据版本安全

### 4.1 Schema v2

`KnowledgeState` 从 `version: 1` 升为 `version: 2`，新增必填 `rejections: RejectedRelationSuggestion[]`。这是真实的结构变化，不是“为了不改版本号而把字段塞进 v1”。

读取规则：

| 输入 | 行为 |
| --- | --- |
| 本地 v1 知识 | `loadKnowledge` 迁移为 v2，`rejections: []`，概念/证据/关系保留 |
| 本地 v2 知识 | 正常读取；无效拒绝条目会被过滤并保留原始副本，界面提示 |
| 本地 v3+ 知识 | 返回空状态、`issue: newer-version`、`writeBlocked: true`；原始字节复制到 `rw.knowledge.corrupt`，任何写入都不会覆盖主键 |
| v1 备份 | `parseKnowledgeState` 接受并迁移为 v2；备份恢复照常进行 |
| v2 备份 | 完整读取拒绝记录；缺字段/坏引用则拒绝恢复，不写入 |
| v3+ 备份 | 严格解析失败，恢复被拒绝，现有数据不变 |

### 4.2 备份与恢复

- 备份容器 `formatVersion` 仍为 1，`app.knowledgeVersion` 变为 2；这是包内元数据，不改变文件框架。
- `countData` 增加 `rejections` 计数。
- `mergeRestore` 增加拒绝记录合并：按稳定指纹去重，按 id 处理同 id 冲突，证据中的 `paperId` 跟随论文身份合并映射，并重算指纹。
- 恢复后的回读校验现在同时比较概念、证据、关系、拒绝数量；数量不一致会回滚。
- 真实工作流导出的 2.27 MB 备份在全新浏览器恢复后：5 个概念、3 条关系、6 条出处、1 条拒绝，版本 2；拒绝记录仍带 `rel1-` 指纹。

### 4.3 旧客户端兼容边界（不能由新代码修复）

旧版客户端的行为是已发布的代码，本轮无法修改。根据旧代码可以明确说明：

- 旧版的严格备份解析只接受 knowledge v1，因此**旧版会用“无法读取”拒绝新备份**，不会把 v2 数据导入成残缺状态；
- 旧版的宽松本地读取不检查版本，会保留它理解的概念/证据/旧关系，丢弃它不认识的新关系类型和 `rejections`，先把原始字节复制到 `rw.knowledge.corrupt`，然后在下一次写入时保存裁剪后的图；
- 新代码无法阻止旧版进程写它自己的 localStorage，也无法让旧版理解新关系类型。能做的保护已经做了：新版本遇到更高版本时完全停写；旧版本至少保留了 `rw.knowledge.corrupt` 原始副本。

因此正式试用期间应保持客户端版本一致；从新版本降级到旧版本前应先导出备份。

- v3 主键只读、写入被阻止、原始副本保留；

### 5.2 实际完成的步骤

1. 核心论文导入项目的核心论文位置（33 页、1,452,162 字节的真实 PDF）。
2. 阅读第 4 页技术定义、第 5 页长度分配/联合填充公式段落。
3. 在真实文字层建立 4 条 DLM 批注：
   - 第 4 页高亮“Common strategies select positions…”；
   - 第 4 页疑问“这里的 shared canvas 与普通上下文窗口有什么本质区别？”；

5. 人工建立 3 个概念：
   - `language model`（跨两篇论文，2 条出处）；
   - `shared canvas`（DLM 第 4 页）；
   - `masked diffusion language model`（DLM 第 4 页）。
6. 人工建立 2 条已确认关系：
   - `masked diffusion language model —definition→ shared canvas`；
   - `masked diffusion language model —extends→ language model`。
7. 从知识视图打开 `shared canvas` 的第 4 页证据，回到原文并返回，选中概念保持。
8. 对真实选区运行离线 mock 知识分析，验证建议、拒绝、撤销、重新出现、采纳、再次拒绝。
9. 导出 2.27 MB 备份，在全新隔离浏览器恢复；继续打开 TSLM 第 3 页证据并返回知识视图。

### 6.2 实际修复

1. **已确认的 AI 关系行仍显示“拒绝/暂时忽略”。** 这两个操作会删除关系记录；虽然拒绝函数会拒绝已确认关系，但“暂时忽略”走的是删除路径，可能把正式关系从知识库删掉。现在只有 `status=suggested` 的行显示拒绝/暂时忽略；已确认行只保留改类型等编辑操作。
2. **打开知识面板后阅读器可能离开选中页。** fit-width 模式下侧栏打开会改变列宽和页面高度；原先只按滚动锚点恢复，真实工作流中第 4 页的选择会在面板打开后落到第 2 页。现在在面板打开、布局稳定后，把面板上下文对应的页面重新滚动到视野（`ReaderView` 中 80ms 后的 `scrollToPage(page, 'auto')`）。浏览器验收明确断言页码保持 4。

没有进行首页、视觉系统或组件级重构。

## 九、未验证的真实 AI 能力

本轮严格离线，以下内容**没有**用真实模型验证，不能写成已验证：

1. 真实 DeepSeek Flash 是否会在下一次分析中重复完全相同的解释和证据。若它改写解释或换引文，同一条学术主张会被视为“不同主张”再次出现——这是指纹规则的设计，但不是对真实模型行为的验证。
2. 真实模型是否能稳定遵守新增的六种关系类型、方向、短上下文上限和拒绝提示。Phase 8.1 已证明它会误用 `prerequisite/extends`；本轮只改了提示词和校验器，没有新真实调用。
3. 真实模型输出的中文/英文概念名在跨语言复用中的长期稳定性。
4. 多设备同时恢复含拒绝记录的备份时，id 冲突和指纹冲突的真实频率。
5. Tauri 桌面壳、系统级快捷键、超大论文（数百页）长期使用。
6. AI mock 建议的学术质量；mock 只用于流程与界面验证，面板已明确标注。

## 十、用户正式试用前的已知限制

1. **拒绝是“这次主张”的拒绝，不是“两个概念永远不能有关系”。** 同一对概念、同一类型但不同解释或证据，会作为新建议出现。这是为了避免把一次 AI 误判扩大成永久禁令。
2. **拒绝匹配依赖文本与证据的精确一致性。** 模型改写解释、换一条引文或调整空格/大小写以外的事实，就会被视为新主张。指纹对空白和大小写做了归一化，但不做语义相似度判断。
3. **概念建议没有持久拒绝，只有暂时忽略。** 本轮按任务要求把持久拒绝用于关系主张；概念仍然可以忽略后重新出现。
4. **旧客户端不能读新备份。** 旧版严格解析只接受 knowledge v1；降级前必须导出并保留新版本，或先升级客户端。旧版宽松读取 v2 localStorage 时会丢弃新关系类型/rejections，并把原始字节复制到 `rw.knowledge.corrupt`；这不是新代码能修复的。
5. **更高版本数据会显示为空且只读。** 这是为了避免覆盖；需要升级到对应版本才能继续编辑。
6. **拒绝记录保留当时的解释和证据快照。** 论文文件被替换后，记录仍然存在，但来源可能已不在当前文件中；它代表读者当时的决定，不重新验证。
7. **指纹是 64 位哈希。** 碰撞概率极低，但不是密码学身份；同一用户知识库规模下可接受。
8. **真实模型质量仍未验证。** 试用期间应把 AI 建议全部当作待核实建议；逐字引文只证明文字存在，不证明关系成立。
