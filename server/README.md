# 本地 AI 精读服务

浏览器端**不保存任何 API Key**。所有模型调用都由这个只监听 `127.0.0.1` 的本地进程完成，
前端只发送结构化请求（哪篇论文、哪一页、哪几段原文、什么问题），由服务端组装提示词。

## 启动

```bash
npm run ai:serve
```

不配置任何环境变量时使用 **mock provider**：不联网、不计费，用于开发与验收。
应用启动本身不会产生任何在线调用。

## 连接真实模型

需要同时设置两项，缺一不可：

```bash
AI_PROVIDER=deepseek DEEPSEEK_API_KEY=sk-… npm run ai:serve
```

这是刻意设计的两道门：只设置 Key 不会生效，必须显式声明使用在线提供方。
界面会在发送前显示「回答来自 DeepSeek …：会调用在线模型，可能产生费用」。

### 环境变量

| 变量                        | 默认值                     | 说明                                            |
| --------------------------- | -------------------------- | ----------------------------------------------- |
| `AI_PROVIDER`               | `mock`                     | `mock` 或 `deepseek`                            |
| `DEEPSEEK_API_KEY`          | 空                         | 仅从环境变量读取，不进前端、不进仓库            |
| `DEEPSEEK_MODEL`            | `deepseek-flash`           | 官方当前型号名；也可填 `deepseek-v4-pro`        |
| `DEEPSEEK_BASE_URL`         | `https://api.deepseek.com` | 必须是 https                                    |
| `DEEPSEEK_THINKING`         | `enabled`                  | `enabled` 或 `disabled`                         |
| `DEEPSEEK_REASONING_EFFORT` | `low`                      | `none` / `low` / `high` / `max`                 |
| `AI_PORT`                   | `8787`                     | 监听端口；监听地址固定为 `127.0.0.1`，不可配置  |
| `AI_TIMEOUT_MS`             | `120000`                   | 单次请求超时                                    |
| `AI_MAX_OUTPUT_TOKENS`      | `8192`                     | 生成上限（**含推理**），256–32000               |
| `AI_ALLOWED_ORIGINS`        | 空                         | 额外允许的 Origin（逗号分隔）；回环来源始终允许 |
| `AI_LOG_REQUESTS`           | 开启                       | 设 `0` 关闭访问日志                             |

模型名与请求格式核对自官方文档 `api-docs.deepseek.com`（`POST /chat/completions`、
`Authorization: Bearer`、`choices[0].message.content`）。使用在线提供方时以 JSON 输出模式
请求，因为引用校验需要可解析的结构。

### 思考模式与生成预算

官方默认是**开启思考模式、推理档位 `high`**。这件事在本项目里必须显式处理，因为
**推理 token 与回答正文共用同一份 `max_tokens`**：一次长时间的思考可以把预算耗尽，
于是 `content` 为空或只有半句。所以：

- 服务端**显式发送** `thinking` 与 `reasoning_effort`，不依赖上游默认值；
- 默认档位取 `low`（够用、延迟与花费有界），可用 `DEEPSEEK_REASONING_EFFORT` 调整；
- `DEEPSEEK_THINKING=disabled` 会把档位强制为 `none`，避免同时发出两个互相矛盾的意思；
- 生成预算（`AI_MAX_OUTPUT_TOKENS`，默认 8192）是**推理 + 正文**的总量；
- 真的耗尽时返回 `incomplete` 类错误并说明原因，而不是把空回答当成正常结果；
- 用量里的 `reasoning_tokens` 是 `completion_tokens` 的**子集**，不是额外相加。

### 这些默认值是被真实调用改过的

首次真实联调（CC BY 4.0 论文，档位 `low`）测到：

| 问题类型                         | 耗时   | 输出 token | 其中推理 | 结果                                    |
| -------------------------------- | ------ | ---------- | -------- | --------------------------------------- |
| 原文解释                         | 21.0 s | 3802       | 2689     | 成功，7 条引用全部通过校验              |
| 公式解释（一个被切碎的公式片段） | 25.5 s | —          | —        | **失败**：4096 全部被推理吃掉，没有正文 |
| 英文翻译                         | 7.4 s  | 1116       | 871      | 成功                                    |

于是：预算从 4096 提到 **8192**，超时从 60 s 提到 **120 s**。
第二行那个失败正是这道防线存在的理由——旧代码会把空串当成正常回答显示成一片空白，
现在它会明确说是推理占了预算。

## 边界

- 只监听 `127.0.0.1`，且**不可配置**——改错一个环境变量不能把它暴露到网络上。
- 只有两个接口：`GET /api/ai/health`、`POST /api/ai/ask`。没有任何形式的转发。
- 提供方、端点、模型全部来自进程环境，**从不来自请求**；页面无法把调用指向别处。
- 请求体上限 256 KB，每分钟 30 次，同时最多 4 个在途请求。
- `Host` 必须是回环地址（防 DNS rebinding）；`Origin` 必须是回环或显式允许的来源。
- 日志只有方法、路径、状态、耗时、段落数与字符数——没有原文、没有问题、没有密钥。
- 系统提示词由服务端从常量组装；**论文文本永远只出现在 `user` 消息的数据块里**，
  并且数据块分隔符会在拼接前被消解。
- 引用一律校验：段落 id 必须是本次发出去的，引文必须是该段落逐字的子串；
  页码只取自服务端自己的段落记录，从不采信模型给出的页码。

## 引用校验保证什么、不保证什么

这是三个不同的问题，只有第一个是机器能查的：

| 问题                               | 谁来判                 | 本服务的态度                                                       |
| ---------------------------------- | ---------------------- | ------------------------------------------------------------------ |
| 引用文字是否真的来自本次提供的原文 | **本服务**（逐字比对） | 保证。不合格的引用会被丢弃并计数，绝不显示成可点链接               |
| 原文是否支持这句话的结论           | 读者                   | **不检查**。用第二个模型给第一个模型打分，只是把不可验证换了个位置 |
| 结论本身是否正确                   | 读者                   | **不检查**，也检查不了                                             |

因此界面在引用下方会写明：「以上引用已核对：引文确实逐字来自本次发送给模型的原文。
引文是否支持这里的结论、以及结论本身是否正确，不在这道校验的范围内。」

`groundedInText` 是**模型的自我判断**，界面照实转述并标明这是它的自述，
不是被核对过的事实。

## 测试时用到的故障开关

mock provider 会识别问题里的几个标记，用来在浏览器验收里走到每条失败路径
（真实模型上它们只是普通文字）：

| 标记                    | 行为                                   |
| ----------------------- | -------------------------------------- |
| `[[mock:error]]`        | 返回模型服务错误                       |
| `[[mock:timeout]]`      | 一直不返回，直到调用方超时或取消       |
| `[[mock:bad-citation]]` | 返回编造的引文与不存在的段落 id        |
| `[[mock:plain-text]]`   | 不返回 JSON                            |
| `[[mock:ungrounded]]`   | 明确表示依据不足                       |
| `[[mock:html]]`         | 回答里带 `<img onerror>` 与 `<script>` |
